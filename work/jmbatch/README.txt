连接错误自动切换线路（双端）

• 漫画接口和图片下载发生连接失败时，优先轮换到其他线路，不再先在同一条线路耗尽重试。
• 针对连接目标显示 `[::]` / `0.0.0.0`、DNS 解析失败、连接拒绝或重置、网络不可达、HTTPS 握手或证书错误，在本次请求中跳过失败线路，尝试其他线路。
• 动态 API 线路与内置备用线路合并并去重，动态列表不再覆盖掉内置备用。成功的 API 线路在当前客户端中优先使用；全部失败后，下次初始化重新获取线路列表。安卓线路缓存最长十分钟。
• 图片请求也会轮换现有图片 CDN，保留原图片路径与下载校验；已完成图片和原单页恢复机制继续保留。
• 每次接口/图片操作最多尝试“候选线路数 + 设置的请求重试次数”，上限重试数为 5；请求重试设为 0 时仍会尝试每条候选线路一次。单次建立连接的超时最多 8 秒，读取超时沿用用户设置。
• 接口切线时显示当前尝试的域名和请求次数；全部失败后，在任务详情汇总失败阶段、各域名、尝试次数及错误类别。

明确报错与处理边界

• 区分异常目标地址、DNS 失败、连接失败、超时、HTTPS/证书错误、服务器响应异常，并提示检查应用联网权限、网络、DNS、代理和过滤设置。
• 异常地址只表示需要排查，不把它直接判定为手机型号缺陷、DNS 污染或某个软件拦截。
• HTTP 401 / 403 / 404 / 429 仍按权限、资源不存在或限流报错，不通过换线反复请求；本地存储错误和取消操作不当作线路故障。
• 保留 HTTPS 证书校验和系统 DNS/代理设置；不硬编码服务器 IP，不强制关闭 IPv6，也不绕过系统联网限制。若全部线路都不可达，软件不能保证恢复连接。
• 线路诊断不包含 Cookie、令牌、完整请求 URL 或漫画请求参数。

JM Batch 0.1.8 — Windows 编号批量下载器
==================================================

快速开始
1. 将 Windows 压缩包完整解压至一个文件夹。
2. 双击 JMBatch.exe。保留旁边的 _internal 文件夹；不需要另外安装 Python。
3. 选择保存目录，以及 PDF 或图片 ZIP 格式。
4. 输入编号后点击“加入队列”，或使用右侧起止编号添加连续区间。
5. 点击“开始 / 继续”。选中任务可查看详细进度、错误和文件路径。

编号示例（仅语法示例，不保证编号存在）
  123456
  JM123456, 123458, 123460
  123456-123460
  123456～123460
  123456 至 123460
支持中英文逗号、空格、分号、换行。区间两端均包含，自动去重。
单次最多添加 2000 个不同编号，队列记录上限 10000。
同编号 + 同目录 + 同格式的重复项会跳过；需要重新下载时先移除旧记录。

文件保存
每个编号生成独立 PDF 或 ZIP，标题中的非法字符会替换。
默认文件名包含随机后缀；可选纯编号命名，遇同名文件时报错。
默认 ZIP 内按 0001/00001.jpg 的形式分章节排列，并含“下载信息.json”。
先下载图片并验证，再生成和校验成品；不输出已知缺页文件。
PDF 页数与预期图片数核对；ZIP 做 CRC 和条目数检查。
默认在导出成功后清理该任务的图片缓存，可在设置中选择保留。
失败、暂停、取消时均保留缓存，不会删除已导出的成品。
输出路径和格式在“加入队列”时确定。顶部改动只影响之后添加的任务。

暂停、恢复与错误
“暂停全部”终止当前工作进程并暂停队列，已完整写入的图片可复用。
“取消选中”跳过选中的未完成任务。需要恢复时可点“重试选中”。
关闭后再打开，未完成队列处于暂停状态，点击开始继续。
“重试选中”使用当前网络设置，保留该任务原来的保存目录和格式。
失败不会阻止后续编号下载。详细原因位于“任务详情 / 失败原因”。
常见错误会区分编号不存在或不可访问、登录/权限、超时、连接、限流、磁盘或导出错误。
“移除记录”只移除队列记录，不删除成品或缓存；移除后不再通过原记录续传。

慢速自动重置
默认：图片 8 线程、单次请求超时 25 秒、请求重试 2 次。
图片阶段先给 30 秒启动宽限，再检查最近 90 秒平均落盘速度；
低于 30 KB/s，或连接/下载阶段连续 180 秒没有进度时，重建工作进程及连接。
每本最多自动重置 3 次，每次等待 3/6/12 秒，超过上限则报错并继续队列。
这些参数均可修改；慢速阈值 0 表示仅检查无进度，取消勾选则关闭自动重置。
重置保留已验证图片，不强制整本从零开始。未写完的 .partial.jpg 不算已下载。
速度由已完成图片的大小估算，不是网卡流量；大图下载过程中可能暂时显示 0。
网络很慢或图片很大时，请延长观察窗口、增大无进度超时或降低阈值。
校验和 PDF/ZIP 导出阶段不受慢速重置影响；如需停止，可手动暂停。

Cookie 与网络
Cookie 为可选项，需登录才能访问的内容可在“下载设置”中填入本人有效 Cookie。
格式：key=value; key2=value2。输入被遮挡，仅保留在本次应用会话内存中。
重启后需要重新填写；不将 Cookie 保存到队列、配置、日志或命令行参数。
没有内置登录浏览器或代理编辑器。下载库会按运行环境采用其网络/代理配置。
服务端可用性、访问权限、限流和接口变化仍可能造成下载失败。

本地数据位置
队列、设置和运行日志：%LOCALAPPDATA%\JMBatch
任务缓存：所选输出目录\.jmbatch-work\任务标识
Cookie 不在上述文件中；编号、标题、目录和错误记录会保存在本机。
可通过环境变量 JM_BATCH_HOME 指定独立配置目录。
同一配置目录只允许打开一个界面实例，避免同时写队列。

安卓迁移说明
此包不是安卓 APK，Tk 界面和 Windows 打包方式不能直接安装到安卓。
core.py：编号解析、配置、状态、错误和文件导出。
worker.py：jmcomic 下载、图片完整性校验和进度事件。
engine.py：队列、进程隔离、暂停恢复和慢速重置。
app.py：Windows 桌面界面。
迁移时可保留事件协议和业务规则；安卓需替换界面、任务执行方式与存储授权，
并验证 Python/JNI 环境、curl_cffi、Pillow 和 PDF 依赖的安卓兼容性。
目前的分层减少迁移耦合，不等于已经解决安卓原生后台下载及打包。

0.1.1 性能修正
明确使用 curl_cffi_session，使同一本中每个工作线程复用 HTTP 会话与连接。
原来的 curl_cffi 模式在每次请求后关闭会话，连接等待会影响逐图下载速度。
新增每次成功任务的准备、连接/元数据、图片下载与处理、校验、导出耗时。
耗时记录在任务详情和 app.log 中，不包含 Cookie 或图片地址。
新版首次配置默认 8 线程；升级保留原设置，所以旧配置仍可能显示 4。
先关闭旧版再打开新版。需要调整线程数时，请打开“下载设置”。
更改设置后新添加的任务会采用新值；已有任务可暂停、选中并“重试选中”。
单击“开始/继续”会保留已加入任务的原参数。
该版本仍然逐图下载并在本地导出，没有改为官网 ZIP 直链下载。
官网整包下载与逐图下载不是同一路径，修正后仍不能保证达到浏览器整包速度。

发布规则
仓库必须为公开仓库，在 GitHub Releases 上传正式版附件：
Windows：JMBatch-主版本.次版本.修订号-Windows-x64.zip
Android：JMBatch-主版本.次版本.修订号-Android.apk
例如 JMBatch-0.1.6-Windows-x64.zip、JMBatch-0.2.5-Android.apk。
同一 Release 必须上传 update-manifest.json 及有效的 update-manifest.sig 签名。
两端可放在同一个 Release，按附件文件名分别比较版本；草稿和预发布版会跳过。
只扫描 API 返回的最近 20 条 Release，选择本平台版本号最高且高于当前版本的附件。
不识别 GitHub 自动生成的 Source code 压缩包，也不使用预发布版本号。
Android 必须保持包名、同一签名密钥并递增 versionCode，才能覆盖安装保留数据。
更新仓库与开关在本机单独保存，不改变任务原有下载设置。
已接入实际发布仓库；当前客户端按平台附件版本判断更新，日期标签不参与版本比较。
真机覆盖安装及未来新版本发布到安装的完整流程仍需设备验收。
